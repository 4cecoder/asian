# convex/

Backend for the web app: schema, auth, and (eventually) query/mutation
functions. See `docs/knowledge/tracks/track-08-convex-db.md` and
`docs/knowledge/adr/0003-auth-architecture.md` for the design reasoning.

## One-time setup (can't be scripted — needs a human)

```bash
cd apps/web
bunx convex dev
```

This will prompt you to log in (browser) and pick a **team** and
**project** — a real account-level decision, so it can't be automated by
an agent. Once it finishes the first sync:

- `convex/_generated/` appears locally (gitignored — regenerated by the
  same command on every machine, never committed).
- `.env.local` gets `CONVEX_DEPLOYMENT` / `NEXT_PUBLIC_CONVEX_URL`
  (gitignored — see `SECURITY.md`).
- Leave `bunx convex dev` running in a terminal while developing; it
  watches `convex/` and pushes changes live.

After that, get the deploy key for CI (`SECURITY.md`'s "Where secrets
actually live"):

```bash
gh secret set CONVEX_DEPLOY_KEY --repo 4cecoder/asian
```

## Seeding real dictionary data

`convex/seed/` holds conversion scripts and generated JSONL for
`dictionaryEntries` — pulled from real, openly-licensed
English↔Asian-language dictionaries (JMdict for Japanese, CC-CEDICT for
Chinese, English Wiktionary via kaikki.org for Korean; see
`convex/seed/README.md` for sources and licenses). Once a deployment
exists:

```bash
bun run convex/seed/build-jmdict.ts     # regenerate convex/seed/dictionary-ja.jsonl
bun run convex/seed/build-cedict.ts     # regenerate convex/seed/dictionary-zh.jsonl
bun run convex/seed/build-wiktionary-ko.ts  # regenerate convex/seed/dictionary-ko.jsonl
bunx convex import --table dictionaryEntries convex/seed/dictionary-ja.jsonl
bunx convex import --table dictionaryEntries --append convex/seed/dictionary-zh.jsonl
bunx convex import --table dictionaryEntries --append convex/seed/dictionary-ko.jsonl
```
